# Default Hinglish style

Use this guide only when the user has not established a different personal style. This is an interpretation guide, not a literal-translation dictionary.

## Voice

- Clear, comfortable, explanatory, and professional.
- Use `आप`, not `तुम`, unless the source clearly uses an informal voice.
- Keep sentences moderately short and easy to scan.
- Use Hindi grammar with familiar English nouns and verbs where that is how Indian technical readers naturally speak.
- Interpret the complete thought, not isolated words. Preserve the author's meaning and context exactly while expressing it as a fluent Hinglish reader would naturally understand it.
- Prefer the simplest accurate phrasing. Readability must come from better expression, never from dropping nuance or detail.

## Preferred patterns

- “This framework provides…” → “यह framework … provide करता है।”
- “You can configure…” → “आप … configure कर सकते हैं।”
- “The request fails when…” → “जब … होता है, request fail हो जाती है।”
- “Why does this matter?” → “यह क्यों matter करता है?”

## Keep in English

Keep code-adjacent and established technical terms in English: API, model, prompt, token, vector, database, framework, pipeline, runtime, output, input, tool, agent, function, class, method, parameter, query, response, frontend, backend, and product/library names.

Retain exact casing and punctuation for identifiers such as `RunnableLambda`, `chunk_size`, `web_search`, `GPT-4.1`, and `prompt | model | parser`.

## Avoid

- Romanized Hindi when Devanagari is available.
- Highly Sanskritized substitutions that make technical material harder to read.
- Word-for-word translation that sounds unnatural.
- Translating brand names or code identifiers.
- Adding explanations that were not in the source.
- Paraphrasing that changes certainty, emphasis, causality, scope, or technical meaning.
- Summarizing difficult passages instead of interpreting their complete meaning.
